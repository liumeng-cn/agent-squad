# PostgreSQL 数据结构与向量检索设计

现有 `schema.sql` 有 53 张表，其中 50 张由平台管理，3 张由 AgentScope SDK 管理。业务迁移以现有表及实际 Mapper 为基线，保留业务 ID、版本、幂等键、租约和事件顺序。以下结构用于 PostgreSQL 迁移和后续 RAG 设计评审。

| 数据 | PostgreSQL 存储 |
| --- | --- |
| 用户、认证与会话 | 保留 `sq_user`、`sq_auth_*`、`sq_conversation`、`sq_message` 及附件关联。保持用户隔离与认证查询的唯一键。 |
| 计划、任务与执行 | `sq_plan` 保存发布后的不可变计划版本及节点定义，继续与 `sq_worker_job`、`sq_goal_task` 在业务事务中协调。保留计划版本及逻辑键唯一约束。 |
| 调度与恢复 | 保留 `sq_command`、`sq_runtime_binding`、`sq_runtime_event_inbox` 和公开事件表。到期时间、租约、游标和收件状态用于重新派发与恢复。Redis 存放可重建的派发引用。 |
| AgentScope 原生记录 | 使用锁定 SDK 的 PostgreSQL JDBC 方言管理 `agentscope_store`、`agentscope_sessions`、`agentscope_snapshots`。会话日志继续通过 SDK API 写入。启用原生 Plan Mode 时，草稿通过 SDK 远程文件系统保存，需验证会话隔离和跨实例恢复。 |
| 显式长期记忆 | 保留 `sq_memory`、记忆修订、授权来源、写入回执和执行范围快照。用户授权、版本、删除和过期继续由现有业务逻辑裁决。 |

PostgreSQL 基线采用 `bigint GENERATED BY DEFAULT AS IDENTITY` 作为内部主键，便于以后显式导入原主键。业务 ID 统一为 `bigint` 雪花 ID：Java 内为 `Long`，JSON 响应仍输出十进制字符串，避免浏览器 number 精度丢失；仅原生会话、回合、运行、事件、模型与能力标识保留字符串。时间字段按现有 UTC 语义选型并验证 JDBC 映射。结构化 JSON 字段逐列检查比较、哈希及序列化依赖后再决定是否用 `jsonb`。MySQL 的 upsert、自动更新时间、空值唯一性及锁语义需要按实际调用验证。SDK 表结构以锁定版本 PostgreSQL 方言生成的结构为准。

后续检索使用三类记录，按用户归属保存，源数据和生成结果各有版本。

| 建议表 | 关键字段与约束 |
| --- | --- |
| `sq_conversation_summary` | `user_id`、`conversation_id`、`generation`、`through_message_sequence`、`summary_version`、`summary_text`、`create_time`。同一用户、会话和代际下版本唯一，生成水位必须属于该代际。摘要由会话授权约束。 |
| `sq_retrieval_chunk` | `user_id`、`chunk_id`、`source_type`、`source_id`、`source_version`、`chunk_no`、`content`、`content_hash`、`expires_at`。来源类型首期为显式记忆或会话摘要。用户、来源类型、来源 ID、来源版本和分块序号组成幂等键。 |
| `sq_retrieval_embedding` | `user_id`、`chunk_id`、`embedding_profile`、`embedding vector(N)`、`create_time`。对分块使用带用户归属的复合外键，每个分块和向量配置只保存一份。配置标识绑定模型版本、维度和距离度量。 |

向量异步生成。写入时再次检查来源仍有效且版本一致。检索先按用户、来源权限、当前版本和过期条件过滤，再按向量距离排序。旧版本、撤销授权或删除的来源应在下一次查询时立即被排除，派生数据可以随后异步清理。任务固定上下文时，应记录使用的来源 ID 和版本，以便恢复时重建同一组输入。

首期使用单一向量配置和固定维度 `N`，等 embedding 模型选定后确定维度。先验证按权限过滤后的精确余弦查询，再用真实数据量和过滤比例评估 HNSW 的召回率及延迟。更换不同维度的模型时使用独立的向量表或分区及索引，回填后切换检索配置。

本地验证容器使用 PostgreSQL 18 和 pgvector，端口绑定在 `127.0.0.1:15432`，数据库为 `agent_squad`，用户为 `squad`。本地 Gateway 与 Server 通过 PostgreSQL JDBC 驱动接入该库。基线由 psql 执行，应用启动时关闭 SQL 初始化。

PostgreSQL 空库脚本见 [schema-postgresql.sql](../server/agent-squad-server/src/main/resources/db/schema-postgresql.sql)。平台表保留字段注释、唯一键和索引，三个 AgentScope 表取自锁定 SDK 的 PostgreSQL 方言。本地验收采用新库及预置测试账号。生产迁移和测试夹具仍需单独适配。

平台业务 ID 统一采用 64 位雪花 ID：库表列为 `BIGINT`，Java 侧使用 MyBatis-Plus 雪花发号器，API 和消息中使用十进制字符串，避免 JavaScript 数值精度丢失。身份、来源消息、附件、任务、会话、绑定、命令、作用域、预算、产物、记忆和活动等入口的 ID 校验均已按十进制格式收敛，OpenAPI 中对应字段使用 `^[1-9][0-9]{0,18}$`。本地种子账号使用固定数字 ID（admin=1、demo=2）。SDK 会话标识（`framework_session_id`、官方日志 `session_id`）、认证会话 ID、外部标识、安全令牌、投递/守卫令牌、幂等键和请求关联 ID 按各自协议保留字符串。雪花节点号须由部署分配并保证不同发号进程之间唯一，发号实现还需处理时钟回拨。内部存储主键继续独立承担索引和分页职责。
