## KV与Journal后端

| 实现 | 协议与物理格式、寻址 | 并发与更新 | 删除、恢复及装配 |

| OssBaseStore | BaseStore；bucket中prefix/ns/key.json与key.version两个对象；JsonUtils Map JSON | putIfVersion先读版本、后写两对象，没有条件写原子性，且未开启supportsAtomicSessionStorage | delete删除两对象；get读JSON+版本；Builder指定OSS客户端bucket/prefix |

## Snapshot后端

【源码确认】LocalSandboxSnapshot存tar文件、RemoteSandboxSnapshot代理RemoteSnapshotClient、NoopSandboxSnapshot丢弃归档。官方远程客户端包括OSS、COS、Mongo、Redis、通用JDBC、mysql包JDBC、Postgres及ControlPlane内部客户端。共同接口仅upload/download/exists，不含通用delete与历史迁移。

- OSS/COS客户端写对象归档，下载返回流，bucket/prefix由各Spec配置。
- RedisRemoteSnapshotClient读完整tar到byte[]，默认agentscope:sandbox:snapshots:<id>.tar，SET再可选EXPIRE，TTL绑定非原子。
- JDBC/Postgres客户端通过方言/SQL写二进制列；Mongo客户端通过其归档存储实现读写。它们不是AgentState序列化。
- ControlPlaneSnapshotSpec内部客户端将归档请求代理至控制面；仅客户端不能证明后端物理位置。

【待验证】本盘点未逐项运行所有后端集成；Snapshot各远程客户端的具体对象路径和字段补充见末节。

## Service与Examples边界

【源码确认】service-common的JpaAgentStateStore是官方服务应用内的Spring/JPA实现：独立userId/sessionId/stateKey查询、stateData JSON文本、listKind标记；getVersioned显式事务后返回UNVERSIONED，不能视为版本CAS后端。删除联动DeletedSessionRegistry；实现依赖JPA Repository，非Harness默认类。

【源码确认】service-dataplane的MemoryStoreFilesystem是官方服务应用内文件路由适配器，不应当作SDK默认Filesystem。examples/codingagent的SqliteBaseStore是示例BaseStore：store(namespace,key,value JSON,version等)，SQL条件CAS、单键delete/get，以示例的DataSource/连接装配；不同于Harness包私有SqliteSessionStorage的BLOB journal。
