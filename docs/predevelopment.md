# 开发准备与交付顺序

2026-10-20，v0.2.1。目的不是无限补文档，而是把开工条件、开发中的验证和上线门槛分开。当前用户安排继续开发前工作；不创建应用、安装依赖或启动服务。

## 1. 当前结论

业务需求、语言路线、模块职责、公开契约与数据设计已有可评审基线；Web工作台也属于一期。还不能把它当作已证明可运行的生产方案。当前可以进入详细任务评审与界面交互评审，应用实现待用户另行安排。

| 准备项 | 本轮状态 | 何时必须通过 |
| --- | --- | --- |
| 需求/边界与验收 | R01–R12及A/B场景已写入 | 开始骨架前确认无明显遗漏 |
| SDK依赖可获得性 | 4个核心模块BETA1 POM返回200；见只读记录 | 开工前先确认，无需安装 |
| 固定SDK源码适配 | 关键API/开关已查；具体映射见适配表 | 首个运行切片前编译与故障实验 |
| 持久一致性 | 已定义权威与崩溃窗口，审批/恢复仍需实验 | 每个相关切片完成时通过 |
| 页面信息架构/接口 | 已补路由/API，工作台/详情/审批静态稿已渲染走查 | 视觉评审；其他页面在对应切片补齐，浏览器交互仍待验收 |
| 构建与基础设施 | 已补配置Schema/示例与池/线程/超时边界，未建应用或容器 | 实现开始时精确依赖锁/迁移验证 |
| 性能/HA/备份 | 目标初值与实验清单 | 集成/上线阶段，不阻塞所有编码 |

不要求编码前完成全部生产压测；也不能先把完整平台写完再验证框架恢复。先做最高风险的薄切片，再沿模块交付用户能跑的功能。

## 2. SDK只读预检

[dependency-preflight.json](research/dependency-preflight.json)记录2026-10-20的HTTP GET：agentscope-core、harness、extensions-jdbc、extensions-model-openai 的2.1.0-BETA1 POM均可获取。未获取JAR、未递归解析依赖、未构建，因此依赖冲突和运行可用性仍未验证。

源码核对保持固定提交，不把main变化当本版行为。源码范围与待实验边界见[sdk-adapter-map](sdk-adapter-map.md)。

## 3. 一期纵向交付顺序

| 工作包 | 后端 / SDK | 页面交付 | 完成条件 |
| --- | --- | --- | --- |
| D0 骨架与兼容探针 | 固定依赖、配置/迁移；MockModel/离线确定性恢复探针 | 登录/工作台交互稿和基础组件规范 | 依赖编译与离线命令持久受理/重启恢复探针已通过；真实SDK持久输入与接管机制仍待D1接入，不先接云效 |
| D1 可用单Agent | 身份、会话、Task受理、Command、Binding、真实持久事件 | 登录、新对话、发送、快照/进度、停止、错误态 | 关页面/杀实例后仍可查，A01–A03/A11–A13与B01–B08核心场景 |
| D2 受控工具与交互 | Connection、Operation、INPUT/APPROVAL、核对、预算基本gate | 追问/审批卡、连接设置、操作详情与核对权限 | 已确认操作不重发；回执丢失可核对，A07/A08/B05/B06/B09/B12 |
| D3 多Worker协作 | 定义、局部Context、Plan/Job、恢复/汇合与重规划 | 任务详情、子任务列表、管理员能力页 | 单/并行/串行/失败分支恢复，A04–A06/A09/A10/A17 |
| D4 Skill与记忆 | 自动发现使用、版本固定、显式记忆及删除屏障 | Skill导入/详情/启用、记忆管理 | 无需会话下拉绑定；权限/记忆不回流，A14/A15/B11/B13 |
| D5 沙箱与交付 | 固定隔离驱动、资源/网络、产物与保留、完整预算 | 上传/产物下载、失败诊断 | 不可信脚本隔离及产物恢复，A16/A18/B03/B10 |
| D6 集成与发布准备 | 多副本、备份恢复、负载与安全回归 | 无障碍/窄屏/视觉走查、整条工作流 | 运行证据和已知限制齐全；不以接口数量代替完成度 |

D2之前仅开放纯读取/模拟工具；D5隔离未通过前不开放任意脚本。后续工作包不改变需求，只改变交付顺序。任何迭代都是可运行切片，但不能把切片可运行说成底座已全部完成。

## 4. 开发任务应交给实现者的内容

每个包必须带：目标场景、修改模块/契约、输入输出、状态与事务、故障注入点、页面状态与入口、自动/人工验收、证据目录及未完成限制。不按“一张表一张CRUD页面”拆任务。

后端与前端共享OpenAPI和事件样例。前端可先用明确标记的静态fixtures设计状态，不把mock成功当真实SDK完成；联调必须改接真实API并走断线/审批/核对路径。

## 5. 评审剩余问题

- D0验证BETA1是否满足恢复/事件接口；不满足时修订适配或固定版本，不能自动降级需求。
- 审批只保留一条业务决定，与原生ASK绑定，禁止双确认或“原生允许就跳过平台”旁路。
- SDK私有日志key长度与三方表长度须按确定标识编码计算，避免正常ID组合就超255。
- 页面的初始SSE游标、登录失效和审批详情已补接口，仍需前端交互稿与实际浏览器验证。
- 费用单价、生产模型/端点、密钥管理后端由部署配置提供；未配置时不接受无限额运行，不需要用户把密钥发到聊天。

配置参数详见[配置基线](configuration-baseline.md)，页面稿见[视觉评审稿](ui/README.md)。这些剩余工作以可验证结果收敛，不再增加与核心运行无关的功能。
