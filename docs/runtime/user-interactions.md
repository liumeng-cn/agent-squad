# 用户提问与确认

V2 聊天通过 `ask_user` 请求用户补充信息、选择方案或确认意愿。工具校验问题和选项后抛出 SDK 的 `ToolSuspendException`，原生日志记录待答事项，当前执行以 `suspended` 结束；公开状态为 `WAITING`，不占线程等待用户输入。

## 本地使用

打开 `http://127.0.0.1:5173/v2/login`，新建对话后发送：

> 请调用 ask_user，问我选择方案一还是方案二，提供这两个选项。收到我的回答后，再介绍所选方案。不要替我选择。

页面展示问题卡片，可选择建议答案或自行输入，点击“提交回答”。确认意愿可以使用“确认”“取消”等选项；这表示用户对当前问题的回答，具体业务写操作仍须由所属 Service 校验权限、幂等与业务条件。

## 接口与状态

- 既有会话快照和 SSE 增加 `interactions`：`requestId`、`turnId`、`question`、`options`。仅公开 `ask_user` 的问题，不透传其他工具载荷。
- `POST /api/v2/chat/answers` 接收 `convId`、`turnId`、`requestId`、`answer`，统一返回 `ApiResult<String>`，`data` 是原生答复命令标识。
- 答案先验证当前用户的对话归属，再核对原生日志中的待答事项、所属轮次和工具身份。不能通过本接口伪造其他工具执行结果或批准任意工具。
- Service 调用 `AgentSession.respond(requestId, answer)`，SDK 以工具结果继续原轮次，不把答案作为新任务发送。受理后可能短暂为 `QUEUED`，随后进入 `RUNNING`，最终完成或产生下一个待答问题。
- `answeredRequestIds` 表示已受理答案的待答标识。页面断线后通过快照核对，避免把响应丢失误判为未提交。

## 幂等与恢复

同一问题的相同答案重试返回 Inbox 中原有答复命令；不同答案返回业务 `409`，不能覆盖已受理答案。空白或超长答案被拒绝。轮次过期、问题不存在或执行仍未停止时返回业务拒绝，不自动转为普通消息。

刷新页面后从原生日志恢复问题卡片，未提交草稿和不确定提交的原答案按用户及对话保存在当前浏览器会话中。不确定结果只能重试原答案；快照确认受理后解除锁定。服务重启后使用原有 SDK 持久化存储读取待答事项，不新增交互状态表，不清理已有数据。

## 验证入口

`ChatInteractionTest` 使用真实 Harness 与脚本模型覆盖挂起、重开恢复、用户隔离、原轮次续跑、拒绝伪造工具结果和答案幂等；`ChatHttpTest` 覆盖接口身份与归属校验。前端交互卡片及 `useChat` 测试覆盖选项、提交锁定、断线重试和快照核对。
