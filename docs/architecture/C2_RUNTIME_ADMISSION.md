# C2 持久原生运行容量 Slot：设计与待验收清单

> 状态：首版代码待验证 / NOT_RUN。默认关闭。它不是生产级多实例运行调度已通过的证据。

## 业务边界

用户提交消息后，202 只表示持久受理。Command Delivery 负责把固定命令送入 AgentScope；投递租约只保护投递记录，不能代表模型或工具已经执行结束。本功能在命令领取事务中为原生运行预留容量，保留原命令 ID、Binding 和 Turn 的归属，避免某个用户独占全部全局执行配额。

### 数据与事务

- `sq_runtime_admission_counter`：按 `GLOBAL`、`USER:<uuid>` 计数，通过 `SELECT ... FOR UPDATE` 串行化。
- `sq_runtime_admission_slot`：以固定 `binding_id` 唯一标识占位；记录原命令 `command_id`、action、原生 `turn_id`、ACTIVE/RELEASED。
- `CommandClaimService.claim` 原子领取命令并占位，满额时事务回滚，使命令保留待领取资格；不同进程共用数据库计数。
- `CommandDeliveryService` 绑定原生同步收据；同原命令投递重试不重复计数；STOP 不占新容量。
- `NativeProjectionService.accept` 看到与占位 Turn 对应的 `run/end` 时，在原生事件持久水位事务内释放；重复事件不能重复计数。
- 原生状态不确定、提交收据丢失或 Turn 无法对应时保持占位，不自动按 60 秒投递租约回收。

## 初版明确限制

1. 启用前必须完成 V3 迁移、设置正数全局与用户配额；不要在已有正在运行的原生 Session 上直接热开启。
2. 多进程共享 MySQL 计数能控制领取时容量，但**不代表** AgentScope 同一原生 Session 多进程恢复已经安全。
3. 当 SDK 投递返回同步收据而原生 `run/end` 已被投影时，仍需要验证延迟回执与补偿路径是否导致长期 ACTIVE；没有验证不得自动手动清计数。
4. 同一 Binding 在同一时间可能有补充指令、控制命令、恢复命令；需真实验证 SDK 运行语义，特别是上一回合结束前又收到新命令的情况。
5. 当前默认关闭，无独立管理接口。高负载容量、管理员禁用与长时间卡住的故障恢复、计数重建和告警尚未完成。
6. 对于 `run/end` 已经到达但 SDK 没能提供原命令收据的情况，保持占位属于安全优先策略，可能损失可用容量，需要人工核对后通过专用运维机制处理。
7. 新增 Java 文件暂未由本机 IDEA 格式化。只完成代码仓库写入，不声称编译或测试成功。

## 回归矩阵（全部 NOT_RUN）

| 场景 | 预期 |
| --- | --- |
| 双进程并发领取，global-limit=1 | 最多一个实际命令进入持久运行占位 |
| 用户 A 已达到 per-user-limit | A 的后续命令继续等待；用户 B 仍可领取 |
| 同一命令投递租约过期后重试 | 不产生第二个 Slot、不重复计数 |
| STOP 对正在运行的绑定 | 不消耗新的容量；安全停止仍有原动作通路 |
| 正常 run/end 事件与水位提交 | 仅释放对应原生回合的 Slot |
| run/end 重复投影 | 不重复扣减全局与用户计数 |
| 回执丢失、原生执行状态未知 | 保守保留 Slot，不误判回合结束 |
| 进程在 claim 提交前崩溃 | 整个事务回滚；不遗留已占 Slot |
| 进程在 claim 提交后崩溃 | Slot 保留并由固定命令恢复 |
| 启动时未执行 V3 迁移但 enabled=false | 旧环境不触发新表查询 |
| 用户禁用、取消、回答完成、Worker 失败、交互等待、重试 | 不错回收、不重复调用危险外部操作 |
| 10/100/1000 并发与长时间运行 | 验证 DB 锁等待、占位公平性和 MySQL 事务耗时 |
