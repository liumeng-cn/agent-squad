# 项目术语说明：统一使用容易理解的表达

> 范围：设计文档、README、中文注释、业务日志和后续用户界面。程序对接字段和第三方协议仍保留固定名称，避免无意义的兼容问题。

| 以前常见的说法 | 以后怎么说 | 在 Agent Squad 里实际指什么 |
|---|---|---|
| 事件投影、Projection | **根据 Agent 执行事件更新业务状态** | SDK 报告已开始、已结束后，系统更新任务/回复状态，并发给前端 |
| 水位、Cursor | **上次处理到的事件序号** | 例如处理到第 128 条，下次从第 129 条接着处理，避免重复和漏处理 |
| 原生日志、Native Journal | **AgentScope 自己记录的执行事件** | SDK 记录模型、工具、回合开始结束等事实；不是普通控制台日志 |
| 幂等 | **同一请求重复提交，不重复执行** | 网络重试只返回原来的处理结果，不再次创建任务或执行外部操作 |
| 受理 / Receipt | **已收到并保存、返回处理编号** | 返回 202 不表示 Agent 已经完成，后续还需后台执行 |
| 命令领取 | **后台执行器接手一条待处理任务** | 多个执行线程不能同时把同一条命令当成新命令执行 |
| 租约 / Lease | **有有效期的执行资格** | 执行器失联后过期，别的执行器可接手；不等于可以重做外部写入 |
| Binding / 运行绑定 | **业务任务关联的 Agent 会话** | 用 bindingId 查这个回复或任务使用的是哪个 SDK Session |
| Scope / 执行作用域 | **一次回复或一个目标任务的执行范围** | scopeId 把命令、预算、工具权限、Agent 运行归在一起 |
| 冻结上下文 | **保存当次执行用到的上下文快照** | 让重试能说明当时依据的是哪版资料，而不是用现在的数据偷换 |
| 最终交付权仲裁 | **确保同一条用户消息只发布一个最终答案** | 普通回复和目标任务都能完成时，平台仍只允许一个发布 |
| 事件重放 | **再次读取之前已经收到的事件** | 重启后补处理老事件，不应重新执行工具副作用 |
| 结果不确定 / UNKNOWN | **外部操作可能已成功，但暂时无法确认** | 先停止自动重复写入，等待查询结果或人工核对 |
| 观测埋点 / Instrumentation | **为关键步骤记录耗时、结果、相关编号** | 不需要打印所有参数和对象 |
| Trace / Span | **一次调用的追踪记录 / 其中一个步骤** | 技术标准名保留，中文解释成完整调用和执行步骤 |
| 测评 / Evaluation | **用固定题目和规则检查 Agent 的质量** | 既测答案，也测工具选择、安全、成本、耗时和恢复能力 |

## 写代码和日志的约定

- 中文注释讲清楚“做什么、为什么、失败会怎样”，不用一个晦涩词替代整句话。
- Java 类型、MySQL 表字段、OpenTelemetry 标准字段等**不能直接全文替换**。例如 NativeProjectionService.java 是现有代码类名，但它上方的注释应直接写“根据 AgentScope 事件更新任务状态”。
- 业务日志用“动作 + 结果 + 关键编号 + 错误分类”。例如：\`Agent执行事件同步失败，稍后重试 bindingId=... errorType=...\`。
- 记录数据大小和摘要，不打印完整 Prompt、用户消息、模型响应、工具参数/结果、Cookie、密钥；大集合不整包转 JSON。
- \`WARN\` 是需要关注但能恢复的问题；\`ERROR\` 留给明确影响业务的失败。用户等待、主动取消不自动算错误。
- 文档首次提及必须保留的标准英文词时，加一句白话解释；后文按白话写。

## 前后对比

**之前：**“按持久水位从原生 Journal 读取稳定前缀，逐条交给事务投影器。”

**之后：**“从上次处理到的事件序号继续读取 AgentScope 的执行事件，按顺序更新业务状态；某条更新失败时，下次再处理，不能跳过。”

**之前：**“与原生投影水位同事务裁决状态。”

**之后：**“更新回复状态时，一起保存本次处理到的事件序号；失败就一起回滚，避免重复生成答案。”
