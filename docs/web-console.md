# Web 工作台设计

2026-10-22，设计 v0.2.1。页面属于一期交付；仓库已有 Vue 工作台源码。单 Master 真实模型正向链路已在隔离库验证；当前页面展示会话中的目标历史与最终答案，前端构建通过，浏览器端人工验收仍待完成。自动生成操作页面不在本期范围。

## 1. 信息架构与页面职责

| 页面 / 路由 | 主要内容和操作 | 权限 |
| --- | --- | --- |
| 登录 /login | 账号密码、明确错误、登录后回原地址 | 未登录 |
| 工作台 /app/conversations/:conversationId? | 会话列表、对话正文、附件、任务状态、追问/审批、取消与恢复 | USER，仅本人数据 |
| 任务详情 /app/tasks/:taskId | Job列表、进度时间线、交互、脱敏操作详情、产物和核对入口 | USER；核对需额外 OPERATOR 资源权限 |
| 技能 /app/skills | 列表、版本与说明、导入预览、文件查看、启用/停用 | USER，个人授权范围 |
| 连接设置 /app/settings/connections | 提供方、环境、资源范围、添加/轮换凭据、停用 | USER，自己的连接 |
| 记忆设置 /app/settings/memory | 显式记忆列表、创建、纠正、删除及在途任务影响提示 | USER，自己的记忆 |
| Worker管理 /app/admin/workers | 版本化能力列表、Schema、发布及停用/撤销 | ADMIN；不自动获得读取其他用户内容权限 |

页面→接口→验收映射以[ui-manifest](../contracts/ui-manifest.json)为机器清单。角色控制导航和交互体验，服务端授权决定最终访问权；知道一个路由不是授权。

任务详情属于同一工作台，不另建一套后台“执行页”。产物下载和审批原文在任务抽屉/详情展示即可，不增加无意义一级导航。

## 2. 工作台布局

```text
┌──────────────────┬───────────────────────────────────────────────┐
│ Agent Squad      │ 会话标题             任务状态   查看详情      │
│ 新建对话         ├───────────────────────────────────────────────┤
│                  │ 用户目标 / 附件                              │
│ 最近对话         │                                               │
│ · 日志与配置检查 │ 助手回复与证据                               │
│ · 上次对话       │                                               │
│                  │ [需要补充信息 / 操作确认卡片]                │
│                  │ [进度摘要：日志分析完成，等待配置检查]       │
│                  ├───────────────────────────────────────────────┤
│ 技能             │ 附件待上传/已就绪                            │
│ 连接 · 记忆      │ 输入目标……                         发送/停止  │
│ 账号/退出        │ 自动使用可用技能 · 数据仅本人可见            │
└──────────────────┴───────────────────────────────────────────────┘
```

聊天区域是主入口，进度/工具/Job细节按需展开；不把一排租约、框架版本、数据库ID或表单当作聊天界面。一级可见动作保持新对话、发送、停止、回复；每一张卡片只解决一个当前问题。

视觉初值：浅色背景、中性色、单一低饱和强调色，正文16px/1.6行高，统一8px间距体系，输入区固定且不遮挡内容；桌面三栏（会话/正文/可选详情），窄屏会话与详情改抽屉。工作台/任务详情/审批已有[静态视觉稿](ui/README.md)并完成渲染查看；其余页面和窄屏状态在对应切片实施前补齐。文字和静态稿不冒充浏览器交互验收。

## 3. 提交目标与恢复

1. 进入页面先 currentUser，再读取会话及 listConversationTasks；未登录转登录，不反复创建新会话。
2. 附件上传到 READY 后才加入 TaskCreate.artifactIds；失败可重传，不把本机路径发给模型。发送中禁重复按钮，当前请求固定 Idempotency-Key；超时保留原key/输入补查或重送，不生成第二个目标。
3. 202 后显示“已接收，等待执行”，按 taskId 读快照；不把本地按钮动画当作任务已运行。已有活动目标时输入独立目标暂不可发，提示先处理当前任务或新建对话；INPUT回复走卡片。
4. 恢复显示只读 snapshot + events。刷新、切会话或重连不会 submit/resume。恢复执行必须由按钮/后端恢复策略显式触发，与恢复画面区分。
5. 活跃目标可能含多个Master轮次，UI只显示一个用户目标；不显示每个内部Turn为一条新的用户消息。只有最终确认答案标记完成。

## 4. 状态与可用动作

| 状态 | 页面文案 / 动作 | 禁止行为 |
| --- | --- | --- |
| QUEUED | 已接收，等待执行；停止 | 假装模型已经生成 |
| RUNNING | 正在处理，显示真实进度；停止 | 用假百分比/定时文本模拟进度 |
| WAITING_WORKERS | 正在并行处理/等待结果；展开任务、停止 | 当成完成 |
| WAITING_INPUT | 显示原问题和输入表单；提交回复、停止 | 在主输入框重发原目标 |
| WAITING_APPROVAL | 显示操作确认卡；同意/拒绝、停止 | 默认勾选同意或自动接受永久授权 |
| RECOVERY_BLOCKED | 给出用户可理解原因、下一步；条件满足时申请恢复 | 自动换新Session绕过问题 |
| RECONCILING | 结果待核对；查看事实，有权限时核对 | 普通用户强行标成功/再次发送 |
| CANCELLING | 正在停止并核对已发操作；仍可查看详情 | 点击后立即标已取消 |
| SUCCEEDED/PARTIAL/FAILED/CANCELLED | 固定最终状态，缺失与已发生操作说明；可提出新目标 | “重试”偷偷恢复终态任务 |

前端按状态给初始动作；所有控制请求携 expectedVersion，409 后刷新快照。不能仅凭旧页面缓存判断某个审批、恢复或取消仍有效。

## 5. 追问、审批与核对

INPUT仅支持受限JSON Schema表单：字符串、数字、布尔、枚举、有限对象及数组；不执行Schema里的脚本、HTML或任意组件。遇到不支持的Schema明确提示能力缺口，不能随意把输入当作字符串通过。

审批卡必须展示操作名称、环境/资源、脱敏参数、影响类型及有效期，数据来自 Interaction.approvalContext；其 requestHash 必须与当前请求一致。前端只提交 approve/confirmedRequestHash，不编辑真正工具参数，不回显密钥，不提供“永远同意”。

用户点击后显示“回复已接收，正在应用”，轮询原 CommandReceipt/快照直到实际应用；失败或审批失效要保持真实状态，不能先把卡片标已执行。重复点击使用原幂等键。

操作核对抽屉通过 OperationDetail 展示脱敏事实和证据；canReconcile 为服务端计算。具权限用户提交明确 disposition 与证据，不提供“忽略未知并继续”按钮。后端再次验证角色、归属和版本。

框架 ASK 和平台 Operation 共用一个审批决定：工具预检先建立稳定Operation和Interaction，原生ASK只绑定该Interaction，不再创建第二张确认卡。生效前两层均校验同一hash，单一决定不代表资源授权永久有效，详见M07。

## 6. Skill、连接与记忆页面

Skill导入先在浏览器预览文本路径/大小/说明，再服务端规范化验证；首次只接受文本包/目录，ZIP解析器未完成时明确不支持，不让用户选完才报笼统异常。启用只是加入个人可用目录，不要求会话选择Skill下拉框。详情显示版本/摘要及真实说明，不显示执行按钮冒充能力。

连接编辑显示“已设置凭据”，不返回原Secret；输入新凭据才触发轮换，留空表示不修改，前端PATCH省略secret字段。密码只在内存表单短暂存在，提交后清除，不放URL、localStorage、日志或错误回显。不提供尚未定义后端的“测试连接”假按钮。

记忆由用户主动创建/纠正/删除；有活动任务引用时提示会重新装配上下文或进入恢复阻塞。页面列出版本冲突并刷新，不静默覆盖新值。

## 7. 前端技术边界

Vue 3 + TypeScript + Vite，Vue Router做路由，Pinia仅管理跨页身份/会话与运行视图；服务端事实不以本地存储覆盖。API DTO从OpenAPI生成/校验，views不直接拼URL或写授权逻辑。依赖精确版本在构建验证时固定。

目标目录：src/app（路由/外壳）、features/auth/chat/tasks/skills/connections/memory/admin、shared/api、shared/ui、shared/lib。网络、SSE reducer、请求幂等键分别封装；业务组件不写一套自己的状态机裁决终态。

同源Cookie部署，SSE用原生EventSource。首次 GET events?after=snapshot.cursor；原生EventSource不能自定义Last-Event-ID请求头，连接内重连由浏览器携带头。后端合法Header优先于after，二者均校验归属。事件名统一message，payload.type区分业务类型；收到后仅按seq去重、按revision替换正文。

EventSource.onerror不暴露可靠HTTP错误码，先close、以普通快照GET判定登录/删除/游标情况，再带新cursor重建连接，退避1/2/4/8/15秒；终态停止订阅。切页/登出dispose旧连接，任务不取消；登录失效清内存授权视图，不能从全局浏览器存储恢复旧用户内容。

Markdown采用受限渲染/净化，禁任意HTML、javascript链接、模型注入的可执行按钮；文件下载后端重验授权。键盘可操作、焦点可见、错误靠文案而非只靠颜色；窄屏不隐藏停止/审批主要动作。

官方依据：[Vue工具链](https://vuejs.org/guide/scaling-up/tooling.html)、[SSE机制](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)。上述页面/状态规则为本项目设计。

## 8. 前端验收

| 编号 | 场景 | 断言 |
| --- | --- | --- |
| B01 | 登录失效/退出换用户 | 回原地址或登录页；旧内容和订阅清除 |
| B02 | 发送超时、重复点击 | 固定幂等键；只出现一个目标 |
| B03 | 附件失败/未READY | 不提交无效引用，有可理解重试入口 |
| B04 | 刷新/切页/断线 | 原任务恢复显示，无新模型执行；无双连接串消息 |
| B05 | 等待输入/审批/部分成功 | 每种状态有正确动作，不混同完成 |
| B06 | 旧审批、409、重复回复 | 刷新事实；不显示未发生的成功 |
| B07 | 取消、在途操作待核对 | 停止中与已取消明确区分 |
| B08 | 新一轮Master/半答案替换 | 一个用户目标；revision替换不拼接 |
| B09 | 任务详情与核对权限 | 无权限无操作入口，直接请求仍被后端拒绝 |
| B10 | 下载不存在/越权产物 | 显示明确错误，无内部路径泄露 |
| B11 | Skill导入启用/停用 | 自动可发现，不要求绑定；错误定位具体文件 |
| B12 | 连接轮换/编辑 | Secret不回显，留空不覆盖；错误不含凭据 |
| B13 | 记忆纠正/删除冲突 | 版本冲突提示；在途影响说明 |
| B14 | 管理员能力发布/普通用户直达 | 合法发布可用；非管理员拒绝 |
| B15 | 键盘/窄屏/Markdown恶意内容 | 可操作且无脚本执行，主要动作可见 |

页面状态、交互稿与组件视觉走查应作为开发任务显式交付，不能用“接口已有”代替页面完成。
