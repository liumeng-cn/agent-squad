# Design

## Context

D4 在 `conversation-first-experience` 主链路验收后实施，依赖其 Message/ExecutionScope/预算和会话交互契约；同时依赖框架 Harness 的 Skill 发现/读取与上下文压缩能力，平台补上传安全、归属、版本固定与显式记忆治理。一期长期记忆只接受用户显式写入，默认自动提取须关闭。见 proposal.md - Why。

## Goals / Non-Goals

**Goals:**
- Skill 内容固定版本、按用户作用域只读分发；执行者自动发现使用，无需会话下拉绑定。
- 显式记忆可写/纠正/删除，删除后任何检查点/摘要/索引不得回流；无法清理时进入可诊断阻塞。

**Non-Goals:**
- 不引入向量库或语义检索；一期只做精确/限量文本检索。
- 不把 Skill 一对一注册成 Worker，不开放自动学习/自动发布。

## Decisions

### Skill 版本固定与只读发布
- 选择：发布时固定 skillVersionId 与包摘要，使用只读发布视图；普通回复 Scope、GoalTask 与 WorkerJob 均固定版本与包摘要，Git HEAD 或同名新版本不改变在途执行。
- 理由：运行可复现，同名新版本不得扰动在途任务。
- 替代：直接挂载可变 Git 仓库（不可复现）。未采用。

### 显式记忆与删除屏障
- 选择：仅用户经受控工具写入 ACTIVE 记忆；纠正/删除重建授权视图并保留 tombstone，注入前回权威 Memory 校验归属/版本/有效期/删除。
- 理由：R09 只要求显式长期记忆，避免默认自动提取复活已删内容。
- 替代：启用框架默认记忆自动合并（违背一期需求）。未采用。

## Risks / Trade-offs

- [框架默认记忆钩子/工具未真正关闭] → 按固定标签核对 disableMemoryHooks/disableMemoryTools，并用 A15 覆盖压缩与后台路径。
- [删除后旧摘要仍含原值] → 删除递增代数并校验 tombstone，无法清理即阻塞相关普通回复或任务的新派发；不只校验有 taskId 的路径。
- [恶意 Skill] → 导入规范化校验（文件数/大小/路径），脚本仅经受控工具与 Sandbox 执行。

## 并行实施与共享契约（用户已确认）

- Skill 任务独占 skill 模块、V15 迁移及技能页面；Memory 任务独占 memory 模块、V16 迁移及记忆页面；Sandbox 任务独占 sandbox/artifact 模块与 V17 迁移。主任务统一修改运行、预算、Agent 注册、OpenAPI、路由和计划勾选。
- 请求/响应、工具输入/回执、执行引用采用明确顶层类型；动态 JSON Schema 仅用于真正开放结构。业务规则归属领域模型或明确服务，Controller 与 AgentTool 不编排持久化。
- ExecutionAuthorizationService 从服务端 Session/Binding 推导 Scope，固定 Skill 版本目录/摘要与记忆修订/引用。模型请求、工具调用、命令恢复和产物提交检查有效性；旧上下文无法证明安全时阻塞，不刷新失效引用继续原生 Session。
- 记忆纠正/删除持久化 tombstone 与代际；Skill 安全撤销持久化授权代际。沙箱已发出请求不可撤回，迟到结果与产物不得绕过屏障发布。
- SDK/沙箱调用在平台事务外执行；预算先事务预留，未知执行/计费保守占用，同意图不换键重发。stage/commit 校验执行归属、guard、摘要，提交失败不标为 READY。
- 分别验证后执行撤销/删除发生在模型或沙箱运行期间的交叉实验；对话改造 IME 与端到端收尾仍单独追踪。

## 当前交付优先级（2026-10-30）

用户确认优先完成使用体验与功能链路。保留用户归属、版本、基本输入校验及已有沙箱隔离；复杂攻击覆盖、安全纵深加固另行安排，不作为本轮功能交付的新增前置。已有防护与未验证项分别记录，不将延期项标为验证通过。

聊天中明确要求记住时，由模型判断显式意图并调用工具直接生效，不增加确认卡。服务端记录当前用户消息原话、归属、版本和幂等键；语义意图依赖模型判断是本期接受的边界。设置页直接保存立即生效。
