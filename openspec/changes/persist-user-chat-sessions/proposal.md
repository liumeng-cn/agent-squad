# Proposal

## Why

当前聊天目录仍返回固定示例，新建和改名不保存；真实 Agent 会话又依赖实例本地工作区，无法可靠地从其他工作目录恢复历史。先完成用户会话保存与历史消息返显，为后续分布式部署保留共享存储基础，同时不引入第二套消息权威或自动恢复执行系统。

## What Changes

- 使用 PostgreSQL 保存最小会话业务目录，支持按当前用户创建、分页查询、改名与归属校验；SDK 的 Agent 标识和会话标识与目录稳定关联。
- 经官方 SDK 公开接口把原生 journal、输入收据、检查点及恢复必需的工作区内容接入 PostgreSQL；保持 SDK 原生结构，不直接查询或修改内部载荷。
- 详情和 SSE 从 SDK 已提交历史生成现有公开消息模型，业务目录只补充标题、归属等元信息；不新增消息表、持久消息投影或后台投影器。
- 页面刷新、重新打开会话和应用重启后能够返显已保存历史；用户下一次主动发送沿用原上下文，显式继续仍受 SDK 恢复准入约束。
- 已完成、未完成和结果未知的执行如实展示；读取列表、详情或订阅不启动执行、不领取执行租约、不自动重试输入或工具。
- **BREAKING**：真实会话接口不再返回演示目录，不再为任意 sessionId 合成示例详情；发送、订阅、停止与继续均要求会话已建档且归属当前用户。新客户端继续沿用首发前建档流程。
- 本期不做自动故障接管、任务扫描调度、消息搜索/统计投影、历史文件导入、会话删除及原生日志清理，也不改造 Redis 为运行持久化后端。

## Capabilities

### New Capabilities

- `chat-sessions`：用户会话目录持久化、用户隔离、分页和改名、共享原生存储及跨重启历史返显。主规格目前不存在此能力；沿用既有 `design-chat-workspace` 草案的能力路径，但以本变更定义正式持久化行为。

### Modified Capabilities

- `v2-chat`：增加建档与归属前置条件，明确基于原生持久记录的 GET/SSE 返显、刷新及重启后的只读恢复边界，保留原生提交幂等和显式继续语义。

## Impact

- 后端：`server/v2-server` 的 ChatSessionService、ChatRuntimeService、ChatService、ChatEventStreamService、ChatSessionConverter、ChatAgentConfiguration 及对应 DTO/VO；新增会话 Mapper/XML 并精简当前未使用的 ChatSessionPO 草案。
- 前端：`web/workbench` 的会话目录 store、ChatView、useChat 和聊天 API；复用现有页面布局、用户分区和稳定消息标识。
- 契约：更新 `api/openapi.json` 中实际 v2 会话接口及枚举，不扩大到归档接口。
- 数据：新增 v2 自有数据库基线与显式初始化入口、相应部署迁移和结构校验；SDK 表遵循固定版本官方 DDL，生产启动只校验、不建表。既有用户表、归档实现和真实数据不清空、不重建。
- 已有变更：`design-chat-workspace` 中“只用 JSON、不保存”的阶段性限制与本期目标冲突，由本变更接续并替代其会话存储部分；其页面及头像工作不变，不修改旧变更文件、不宣称旧任务已完成。归档同步时需要避免再用旧 mock 规格覆盖正式能力。
- 验证：扩展现有真实 Harness/脚本模型及 PostgreSQL 验证，增加两用户隔离、真实服务接口和浏览器刷新/重启回归；真实模型调用不作为无条件执行步骤，需遵守对应授权。
