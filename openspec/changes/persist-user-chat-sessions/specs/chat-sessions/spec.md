# Spec Delta

## Purpose

为登录用户提供可持久保存、重新打开和安全隔离的聊天会话目录，将业务会话身份与原生聊天历史关联，使页面刷新和应用重启后仍能返显已有消息及执行事实，而不依赖实例本地工作目录或自动继续历史执行。

## ADDED Requirements

### Requirement: 用户会话建档

系统 SHALL 为当前登录用户保存会话标识、固定 Agent 关联、标题、标题来源、编辑版本和审计时间。相同用户与 sessionId 重复建档 MUST 返回同一条记录，不重复创建原生执行；创建成功响应只在业务记录提交后返回。

#### Scenario: 首次发送前建档

- **WHEN** 用户在新对话首次发送，客户端以稳定 sessionId 请求创建会话
- **THEN** 服务返回已保存的会话摘要，标题为“新对话”、标题来源为 AUTO、初始编辑版本为 0
- **AND** 客户端建档成功后才提交消息；单独创建会话不调用模型或工具

#### Scenario: 创建响应丢失后重试

- **WHEN** 会话已创建但响应丢失，用户再次使用相同 sessionId 创建
- **THEN** 返回原记录及当前标题和版本，不覆盖已修改的标题，不生成第二条会话记录

#### Scenario: 建档成功但发送未成功

- **WHEN** 会话创建已提交，后续消息发送尚未被确认接收
- **THEN** 会话仍保留在用户目录中，已建档但没有已接收输入的会话展示空历史
- **AND** 页面保留草稿和不确定提交信息，不因存在目录记录而判定消息已接收

### Requirement: 全链路会话归属校验

系统 SHALL 使用已认证的服务端用户身份查询会话目录，并在详情、改名、发送、订阅、停止、继续之前校验归属。不存在和不属于当前用户的会话 MUST 返回同样的业务不可访问结果，不暴露其他用户的存在性、标题、消息或执行标识。

#### Scenario: 越权访问

- **WHEN** 用户使用其他用户的 sessionId 调用详情、改名、发送、SSE、停止或继续
- **THEN** 请求被拒绝，业务错误码为 404，不读取对方原生历史，不创建执行或订阅
- **AND** SSE 在建立事件流之前完成校验，不先发送心跳或快照再拒绝

#### Scenario: 不同用户使用相同会话标识

- **WHEN** 两个用户分别以相同 sessionId 建档并聊天
- **THEN** 会话目录和原生执行身份分别隔离，彼此无法获取对方消息、收据、标题和工具过程

### Requirement: 真实会话分页目录

系统 SHALL 只返回当前用户已保存的会话，不混入演示数据；分页以创建时间和内部唯一标识倒序形成稳定顺序，改名、阅读和消息执行不改变排序键。limit 默认 30、范围 1 至 100，cursor 必须校验格式并绑定当前用户与排序规则。

#### Scenario: 分页读取

- **WHEN** 用户分多页读取自己的会话目录
- **THEN** 返回 items、nextCursor、hasMore、serverTime；items 不重复，最后一页 nextCursor 为空且 hasMore 为 false
- **AND** 翻页期间新建会话不挤占旧游标后的记录，重新读取首页可看到新会话

#### Scenario: 空目录与无效游标

- **WHEN** 用户没有已保存会话
- **THEN** 返回空 items，不返回固定示例
- **WHEN** limit 越界或 cursor 损坏、排序版本不匹配、属于其他用户
- **THEN** 返回业务错误码 400，不退回未受限的全量查询

#### Scenario: 摘要数据来源

- **WHEN** 返回会话列表或详情摘要
- **THEN** 标题和版本来自会话目录，hasMessages、lastActivityAt 和执行观察来自当前会话的持久历史；没有已接收输入时 lastActivityAt 使用创建时间
- **AND** lastActivityAt 不作为本期分页排序键；读取失败不得伪装成无消息或已完成

### Requirement: 会话标题并发编辑

系统 SHALL 保存去除首尾空白后的非空标题，长度不得超过 120 字符；改名按客户端提供的 version 条件更新，成功后 titleSource 为 MANUAL、version 递增，版本不匹配返回业务错误码 409。

#### Scenario: 改名后刷新或重启

- **WHEN** 用户改名成功后刷新页面或重启服务
- **THEN** 列表与详情仍显示新标题和最新版本，创建重试和后续聊天不覆盖手动标题

#### Scenario: 两个页面并发改名

- **WHEN** 两个页面使用相同旧版本提交不同标题
- **THEN** 只有一个更新成功，另一个收到版本冲突并重新读取最新摘要，不自动覆盖已保存标题

### Requirement: 共享持久化与历史返显

系统 SHALL 将会话目录、已接收输入、已提交消息、执行检查点及恢复必需数据保存到实例外的共享持久存储。历史返显 MUST 从原生持久记录读取并转换，不能依靠持久消息副本、页面缓存或旧实例本地目录。

#### Scenario: 更换工作目录后恢复已完成会话

- **WHEN** 会话完成后原进程停止，新进程使用不同且无旧文件的工作目录连接同一存储
- **THEN** 同一用户可以从列表打开同一会话，看到相同标题、已提交消息标识、正文、顺序和完成状态
- **AND** 读取历史不增加模型调用次数、工具调用次数或新的原生命令

#### Scenario: 历史读取失败

- **WHEN** 数据库不可用或原生已提交记录读取失败
- **THEN** 返回可识别的服务故障，不能返回演示数据、空历史或假成功
- **AND** 页面保留已经显示的消息并提示重新读取，不清空对话或自动发送

#### Scenario: 不自动导入旧数据

- **WHEN** 新存储方案启用且实例曾留有本地会话文件或旧候选表
- **THEN** 不自动扫描、导入、删除或重建旧数据；正式目录只呈现本方案已建档的会话

### Requirement: 刷新与重新打开会话

系统 SHALL 通过当前会话路由重新加载保存的历史，先展示详情快照，再通过独立订阅更新；页面缓存只能保存草稿、未确认输入和界面偏好，不能成为已保存聊天历史的唯一来源。

#### Scenario: 当前会话刷新

- **WHEN** 用户在带 sessionId 的会话页面刷新
- **THEN** 页面恢复同一会话并立即展示详情返回的已有消息，无须等待新模型输出；订阅迟到或重连不得重复消息或回退游标

#### Scenario: 从空白入口重新打开

- **WHEN** 用户进入不带 sessionId 的聊天入口或清除浏览器本地缓存后重新登录
- **THEN** 展示可用的真实会话列表，用户可选择旧会话；空白入口继续用于新对话，不强制跳转到最后会话

#### Scenario: 切换用户或快速切换会话

- **WHEN** 用户退出登录、切换账号或在两个会话间快速切换
- **THEN** 旧请求、改名响应和订阅快照不能覆盖新身份或新会话的页面状态，草稿和未确认输入按用户与会话隔离

### Requirement: 历史数据公开边界

系统 SHALL 仅返显公开消息正文、稳定消息与执行关联标识、时间及允许展示的过程状态，不返回系统提示词、工具原始参数或结果、完整检查点、凭据及内部序列化数据。

#### Scenario: 查看包含工具调用的历史

- **WHEN** 用户重新打开包含工具调用和子 Agent 过程的会话
- **THEN** 仅展示现有公开协议允许的工具摘要与状态，不从原始载荷新增隐私字段，不把子 Agent 的内部上下文直接展开为用户消息
