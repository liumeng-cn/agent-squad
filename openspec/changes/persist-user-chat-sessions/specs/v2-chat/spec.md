# Spec Delta

## MODIFIED Requirements

### Requirement: 会话与交互身份

系统 SHALL 按服务端用户、已建档会话关联的固定 Agent 和 sessionId 定位会话，并在访问原生执行前校验会话归属；interactionId 标识一次发送。新任务直接以 interactionId 调用原生 submit，重复提交相同输入不得重复执行；复用标识提交不同输入必须拒绝。

#### Scenario: 连续发送

- **WHEN** 同一会话完成首轮并发送下一条消息
- **THEN** 原生上下文保留，返回新的 turnId；恢复执行可使用同一 turnId 下的新 runId

#### Scenario: 未建档会话发送

- **WHEN** 用户向未创建或不可访问的 sessionId 发送消息
- **THEN** 返回业务不可访问结果，不隐式建档、不调用模型，不把任意原生 sessionId 作为授权依据

#### Scenario: 已完成会话重启后继续聊天

- **WHEN** 服务重启后用户读取已完成会话，再主动发送新输入
- **THEN** SDK 使用原会话持久上下文完成新轮次，不把页面返显的正文重新提交为历史，不重复执行旧轮次

### Requirement: 提交与订阅分离

系统 SHALL 由 POST /api/v2/chat/messages 返回 ApiResult 收据，后台执行由原生 AgentSession 持有。独立 GET 详情和 GET SSE 在会话归属校验后读取原生持久历史，返回带执行和输入游标的完整公开快照及会话摘要；同一实例相同用户和会话共享读取，订阅结束后释放读取资源。

#### Scenario: 断线和刷新

- **WHEN** 页面刷新或连接断开后重新订阅
- **THEN** 恢复公开历史和当前状态，不重新提交输入，不取消后台执行，不把观察故障标记为执行失败
- **AND** 快照仅含用户正文、助手正文、工具状态及主模型明确返回的思考文本，不含提示词、工具原始载荷或加密推理元数据

#### Scenario: GET 与 SSE 交错返回

- **WHEN** 详情快照与订阅快照交错抵达，或订阅重连返回相同快照
- **THEN** 前端按会话身份及双游标合并，不重复消息、不回退已展示的提交前缀；相同游标下更新的租约观察状态可以更新展示

#### Scenario: 服务重启后读取

- **WHEN** 服务重启或另一实例打开已保存会话并建立详情读取、列表读取或 SSE
- **THEN** 读取不启动执行调度、不提交命令、不申请执行租约、不调用模型和工具
- **AND** 展示已提交消息与已接收输入，不承诺恢复未持久化的流式片段

#### Scenario: 已接收但尚未启动的历史输入

- **WHEN** 服务停止前输入已被持久接收，但没有开始执行，重启后用户仅打开会话
- **THEN** 保留原输入收据并展示 QUEUED，不自动重新提交或启动该输入，不把 QUEUED 解释为已存在执行进程

### Requirement: 停止和显式继续

系统 SHALL 使用 runId 约束原生 interrupt；页面显示正在停止直到原生日志确认结果。中断或失败轮次可显式请求 resume，未确认工具结果和待答交互仍遵循 SDK 准入，不自动重试外部操作。停止与继续必须校验会话归属；应用启动、历史读取、页面刷新和订阅重连 MUST NOT 自动继续执行或接管其他实例的任务。

#### Scenario: 停止期间的展示

- **WHEN** 停止请求已接收但执行尚未结束
- **THEN** 保留已有正文并展示正在停止；不能仅凭停止收据宣布执行结束

#### Scenario: 执行中进程退出

- **WHEN** 进程在执行中退出且原生执行租约已经失效，用户重新打开会话
- **THEN** 保留已提交正文和过程，展示中断而非完成；不新建执行、自动领取租约或重放工具
- **AND** 租约尚未失效或执行结果尚不明确时不抢先宣告已完成，不仅凭本实例没有执行对象判断其他实例已停止

#### Scenario: 显式继续与未知工具结果

- **WHEN** 用户主动请求继续中断轮次
- **THEN** 使用原生恢复接口，在 SDK 准入允许时创建该轮次的新 run
- **AND** 有未确认工具结果或待答交互时保留拒绝与待处理状态，不绕过准入，不静默新开轮次或重复外部操作
