# Proposal：C4 正式在线发布工程、监控与灾备门槛

## Why

当前项目有较多真实 MySQL/SDK 集成测试，但仓库无 CI 工作流、独立生产配置、可观测指标、可靠的数据库迁移作业与完整备份还原演练。`server` 开发配置监听 127.0.0.1，Gateway 使用进程内配置认证（由 C1 替换）。多用户公网服务需要可靠发布、回滚、密钥与网络隔离、负载/故障实测和隐私控制。

## Scope

- 建立 CI / 可复现构建 / 镜像 / staging 部署描述；生产服务启用明确 secure profile，不执行启动 DDL。
- 统一 requestId/traceId + commandId/taskId/executionId 等关联日志，增加 Spring Actuator/Micrometer 指标和健康检查，保证不记录密钥或完整 Prompt。
- 建立备份/还原演练、数据库迁移与回滚操作手册、容量与安全测试；记录能力边界和未解决风险。
- 做正式上线前验收清单，不自动开通公网域名、购买云资源、改变生产库、推送镜像到公开仓库或执行真实外部写业务。

## Non-goals

- 不做跨地域容灾、多活、Kubernetes/operator、付费计费、组织共享与邮箱营销。
- 不凭模拟压测宣布生产 SLA；容量目标由实际 staging 测量和用户选择决定。

## Acceptance

CI 构建 + 单元/集成测试不隐性跳过；独立 staging 双用户 E2E 通过；敏感日志扫描和 OpenAPI 校验通过；完整备份恢复演练完成；至少一项真实故障注入和压力测试有结论；上线开关全部可控。正式生产发布另需用户明确批准。
