# Spec Delta

## Purpose

为对话中的受理说明、过程输出、正在生成的答案及正式交付建立清晰协议，保证流式体验、重试恢复与唯一终稿一致，并说明文件就绪、目标完成和外部影响之间的区别。

## ADDED Requirements

### Requirement: 输出用途明确
系统 MUST 区分受理说明、过程说明、答案草稿与正式答案；任务创建成功后可直接依据持久事实展示受理说明，不需要额外模型回合。过程文本和工具回执不得自动变成正式答案。

#### Scenario: 创建目标后及时反馈
- **WHEN** 目标及启动指令已可靠保存
- **THEN** 页面展示任务受理说明及任务关联，最终答案发布资格仍由该目标持有

### Requirement: 流式输出只包含允许内容
系统 MUST 仅向用户输出允许公开的文本与资源摘要，不得将模型内部推理、工具参数、凭据或子任务内部上下文当作流式答案；缺少可靠用途信息时不得猜测公开。

#### Scenario: 模型同时产生工具参数和正文
- **WHEN** 一个模型回合包含工具调用及文本
- **THEN** 用户仅接收通过公开规则的内容，工具参数不因包含答案字段而被直接推送

### Requirement: 输出尝试可去重与恢复
系统 MUST 为输出和尝试提供稳定身份与明确的增量偏移；重复增量可忽略、缺口可恢复，不同尝试不得拼接。临时尚未持久的流必须声明其恢复限制，并由权威快照或正式答案纠正。

#### Scenario: 生成过程中取消
- **WHEN** 用户停止正在生成的回答
- **THEN** 已展示文本保留为中断输出，后续旧增量不能把它改成完成答案

#### Scenario: 文本包含非基本多文种字符
- **WHEN** 增量包含中文、表情或组合字符并发生重传
- **THEN** 偏移规则一致，不重复或损坏文本，正式正文可校验

### Requirement: 正式交付唯一且有版本
系统 MUST 按源请求及交付代际裁决唯一正式答案，原执行恢复不创建新交付代际；正式答案、采用的产物引用和发布事件必须一致。迟到旧结果不得覆盖新代际或更新版本。

#### Scenario: 回复转交目标后都尝试完成
- **WHEN** 来源回复和目标均产生可用答案
- **THEN** 仅当前交付所有者能够发布正式结果，来源回复可保留受理说明但不得产生第二份终稿

### Requirement: 文件就绪与任务完成分离
系统 SHALL 展示文件来源、用途和所属计划版本；暂存文件不得下载，公开文件可先于目标完成。失败、取消或计划替换不应声称撤销已发生的下载，正式交付必须明确采用哪些文件。

#### Scenario: 文件就绪后任务部分失败
- **WHEN** 已生成可下载文件，但其他必要工作未完成
- **THEN** 页面保留文件并说明结果限制，不将文件就绪当作目标全部成功

### Requirement: 发布和通知可以独立恢复
系统 MUST 在答案发布后可靠补发通知；客户端断开或通知失败不得重复生成答案、重复运行工具或撤销业务结果。已发布内容仍受归属、会话代际和访问权限约束。

#### Scenario: 发布后连接中断
- **WHEN** 正式答案已保存而页面未收到完成事件
- **THEN** 重连可恢复同一正式答案，不产生第二次模型或工具执行
