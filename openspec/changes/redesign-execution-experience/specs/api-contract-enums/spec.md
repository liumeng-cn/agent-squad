# Spec Delta

## ADDED Requirements

### Requirement: 执行协议有限值使用明确类型
系统 MUST 为回复、目标、节点、活动及尝试状态、等待原因、输出用途、交付状态和计划汇合策略提供明确的枚举契约；不同业务对象的状态不得由一个无边界字符串字段替代，非法请求值必须拒绝。

#### Scenario: 非法活动状态被拒绝
- **WHEN** 接口请求携带不在契约内的有限值
- **THEN** 系统返回参数错误，不将非法字符串写入业务状态

### Requirement: 前后端与存储映射一致
系统 MUST 保持后端类型、数据库值映射、接口枚举及前端联合类型一致，新增或移除取值时同步修改并验证；业务转换必须依据类型及合法转换规则，不依赖散落的魔法字符串集合。

#### Scenario: 增加依赖失败结果
- **WHEN** 系统引入节点因依赖失败未执行的状态
- **THEN** 后端、数据库映射、接口和前端均识别该状态，页面不会将其显示成运行中或成功

### Requirement: 未识别运行事实不伪造成功
系统 MUST 将无法识别的外部运行结果映射为明确的未知或不兼容处理，保留安全诊断信息；未知可选事件与影响完成裁决的必需事件必须采用不同处置，不能一律静默跳过。

#### Scenario: 新版本运行结果无法识别
- **WHEN** 收到当前映射版本无法理解的必需结束结果
- **THEN** 系统阻止据此成功交付并暴露核对原因，不回退为正常完成
