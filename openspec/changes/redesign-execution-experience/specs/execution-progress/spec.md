# Spec Delta

## Purpose

让用户通过真实计划步骤与执行活动理解系统当前在做什么、已经完成什么以及是否需要操作；进度能够在并行执行、计划变更、断线和重启后恢复，并与任务、工具及交付事实一致。

## ADDED Requirements

### Requirement: 进度由真实活动产生
系统 SHALL 按准备资料、安排任务、执行任务、检查结果及汇总交付组织已发生的活动；模型处理、读取文件、发布计划等具体活动必须有真实执行依据，不强迫简单聊天经过全部阶段，不显示内部推理或原始工具参数。

#### Scenario: 附件已经包含在上下文
- **WHEN** 系统未实际调用附件读取而直接处理已准备的资料
- **THEN** 页面可以显示资料准备和模型处理，但不伪造独立文件读取活动

#### Scenario: 工具尚未派发
- **WHEN** 工具请求已形成但仍在等待审批或调度
- **THEN** 页面显示对应等待，不显示工具正在执行

### Requirement: 当前计划决定步骤归属
系统 MUST 使用当前计划的真实节点与依赖展示步骤，并保留旧计划、结果复用及尝试历史；成功、失败、运行、等待、跳过分别计数，不以结束数量代替成功数量，不在没有可靠总量时制造百分比。

#### Scenario: 多节点并行
- **WHEN** 两个节点执行、一个成功、一个等待依赖
- **THEN** 页面同时保留各节点活动并显示对应数量，不由最后一个事件覆盖整体进度

#### Scenario: 新计划复用结果
- **WHEN** 新计划复用旧节点结果
- **THEN** 页面标记沿用结果与来源，不生成虚假的本次执行耗时

### Requirement: 等待和可操作项明确
系统 SHALL 区分执行容量、依赖、输入、审批、外部核对及恢复等待，展示安全原因与服务端允许的操作；页面连接状态 MUST 与业务执行状态分开。

#### Scenario: 页面连接中断
- **WHEN** 页面失去事件连接而后台仍执行
- **THEN** 页面提示连接中断，不将任务改成失败、暂停或取消

### Requirement: 进度可通过快照和增量恢复
系统 MUST 提供一致版本快照和有序可去重的公开事件；重连、缺号或事件超出保留范围时明确补齐或重读快照。旧快照或旧实体版本不得覆盖新状态，正常活动更新不要求重新读取完整会话。

#### Scenario: 快照后产生新事件
- **WHEN** 快照返回的同时后台产生后续活动
- **THEN** 客户端从快照对应序号接续，既不漏事件也不重复步骤

#### Scenario: 事件保留范围外重连
- **WHEN** 客户端携带过期游标重连
- **THEN** 系统明确要求重置快照，不静默忽略缺失历史

### Requirement: 进度处理有界且不改变执行
系统 MUST 限制进度缓冲与单次返回规模；慢客户端和观测不可用不得阻塞执行或改变任务结果。读取进度不得触发新的模型或工具执行，历史缺失事实不得补造。

#### Scenario: 慢客户端积压
- **WHEN** 客户端消费速度低于事件产生速度
- **THEN** 系统合并允许合并的更新或要求快照恢复，不无限积压，不停止其他用户执行

### Requirement: 活动历史保持归属和权限
系统 MUST 将活动关联到源消息、实际执行、步骤和尝试，重新校验访问权限；会话删除或授权失效后既有订阅不得继续泄露内容，用户不能通过活动标识访问其他用户信息。

#### Scenario: 执行期间权限撤销
- **WHEN** 用户访问权限失效而事件连接仍存在
- **THEN** 系统停止受限内容推送，并禁止后续活动详情读取

### Requirement: 当前进度热状态可重建且不回退
系统 MUST 使当前进度缓存携带会话代际、计划、尝试、实体版本和已提交水位，并在授权后访问；缓存缺失从持久事实重建，过期或心跳丢失不得被当成任务失败，临时预览不得裁决完成。

#### Scenario: 缓存丢失后读取
- **WHEN** Redis热进度被清空而执行事实仍存在
- **THEN** 系统重建有依据的当前摘要，缺失细节保持未知，不启动模型补造进度

#### Scenario: 旧快照晚于新事件回写
- **WHEN** 较旧版本的摘要在新活动之后返回
- **THEN** 缓存和页面均拒绝回退到旧版本

### Requirement: 页面通知共享且允许补读
系统 SHALL 按会话共享后台事件读取并跨实例通知在线连接；离线通知丢失时依据持久公开水位补读，不为每条连接维持高频独立数据库轮询。

#### Scenario: Pub/Sub通知丢失
- **WHEN** 更新提示在订阅断线期间丢失
- **THEN** 共享hub的补漏或客户端重连恢复已提交事件，不将缺少提示解释为业务未发生

### Requirement: 正常交互直接应用事件
系统 MUST 使普通聊天的受理、执行进度和公开正文事件具有直接更新页面所需字段，正常处理不得通过每事件全量快照请求替代增量应用。快照只用于首次加载、断线恢复、缺口/过期或明确协议不兼容。

#### Scenario: 普通回复持续更新
- **WHEN** 页面持续收到同一会话连续且受支持的进度与正文事件
- **THEN** 页面直接应用对应实体及正文增量，不重复请求完整快照，不通过额外模型调用生成显示状态

### Requirement: 页面不拥有执行生命周期
后台任务 MUST 独立于SseEmitter及页面存活执行，先保存可恢复事实再对外推送；关闭连接仅释放订阅资源。

#### Scenario: 关闭页面后在另一设备恢复
- **WHEN** 原页面断开而后台继续产生输出，用户在另一设备打开会话
- **THEN** 后台执行不中止，新页面从快照及其后事件接续，不重新提交历史任务或重复工具效果
