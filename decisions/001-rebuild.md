# ADR-001：独立新项目与复用门槛

2026-10-20。已确认：新起项目，先按模块做详细设计，精确到接口和数据结构；旧项目不再作为需要继续兼容的主体。

## 1. 不继承的内容

不复制旧仓库的服务骨架、Workspace 命名、gRPC 主循环、手写 Skill 聊天驱动、ActionJob/Task 双生命周期、页面生成、固定云效流程、前端、迁移序列、私有配置或数据库。旧实现不约束新接口和新表。

旧项目保持原状，供查阅经验。新项目没有指向旧项目的运行依赖、数据库连接或 Git remote。

## 2. 允许逐项评估的资产

| 旧资产 | 允许参考或迁入的部分 | 迁入门槛 |
| --- | --- | --- |
| models/chat_completions.py 与错误处理 | 通用 HTTP 传输、原生 tool call 解析、错误脱敏 | 接入新 ModelPort，取消业务输出结构，补新边界测试 |
| ConnectionSecretCipher | 加密算法、轮换与密钥引用思路 | 与新 Connection/租户作用域契约对齐，无硬编码本机路径 |
| Runner 隔离 | 资源限制、固定镜像、网络代理和清理经验 | 只通过新 Operation/Artifact 协议执行，不能保留旧 callback 旁路 |
| 参数/包校验 | UTF-8、路径、压缩炸弹、JSON Schema 等独立校验 | 不要求 ui.json 或旧 Skill manifest，不携带旧页面字段 |
| 身份与 CSRF 测试 | 可信头、防越权、Cookie 安全的断言 | 针对新入口重新验证，不直接搬旧账号/会话服务 |
| 租约/Outbox/幂等经验 | 原子领取、fence 和事务边界 | 必须符合新状态机；不以复用旧表或接口为前提 |
| 框架实验 | 确定性实验方法和故障窗口证据 | 原版本/后端边界明确；不能当作新项目框架已接入 |

“可参考”不等于“保留原文件”。当前新目录只包含设计资产，尚未迁入任何应用源码。

## 3. 技术路线更新

Java + AgentScope 路线以 [ADR-002](002-agentscope-java.md) 和[整体架构](../docs/architecture.md)为准。此前 Java/Python + LangGraph 建议已撤回；旧项目复用门槛仍有效。
